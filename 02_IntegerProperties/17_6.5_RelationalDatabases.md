1. N-ary Relations
- A binary relation connects two sets: A x B

- A n-ary relation generalizes this to n sets: A1 x A2 x ... x An

- A realtion on these sets is a subset: R ⊆ A1 x A2 x ... x An
Each element of the relation is an n-tuple.

EX:
(w,x,y,z)
- Is a 4-tuple.

EX2:
- Provided a relation consisting of 4-tuples:
(w,x,y,z) ∈ R^4
- With the condition: w = yz

SO: (3,12,4,9)
- Belongs to the relation because:
3(12) = 4(9)
36 = 36

RECOGNIZE:
- When asked whetehr a tuple belongs to a relation: "Substitute the tuple's values into the relation's condition and verify it."

4) Queries
- Is a request for a particular set of data from a database.

EX:
- How many flights used a particular aircraft?
- Which flights leave LAX on a particular date?
- What is the earliest flight between two airports?

RECOGNIZE:
- When the question asks: "Which records satisfy this condition?"
: You'll use "SELECTION".

- When the question asks: "Which attributes/columns do I want to see?"
: You'll use "PROJECTION"

5) Keys
- Is an attribute or set of attributes that uniquely identifies every tuple in the database.

RECOGNIZE:
Ask: "Can two different rows have the same values?"
- If yes -> it is not a key by itself.
- If no -> it can serve as a key.


EX:
- In the airline table, Flight Number alone is not key.
BECAUSE: Flight: 2262, appears twice

- The dates are different.
THUS: Flight Number along is not unique.

THE combination: Flight Number + Date
- Uniquely identifies those flights in the displayed database.

7) Selection Operation
- Choose n-tuples that satisfy a specified condition on their attributes.

Selection = choose rows.

RECOGNIZE:
Look for a condition such as:
Departure Airport = LAX
or:
Date <= 07/03/2013
The rows that satisfy the condition remain.


EX:
Select[Departure Airport = LAX]

Section with Multiple Conditions
Select[Departure Airport = LAX ^ date <= 07/03/2013]

RECOGNIZE:
^ - Means AND
